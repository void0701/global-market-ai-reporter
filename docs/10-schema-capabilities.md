# 10. スキーマと実現できることの対応表

最終更新: 2026-11-23

**「どのデータがあれば何ができるか」の対応表。** スキーマ拡張を判断するときの参照資料。

この文書の目的は、**判断を急ぐべきものと後回しにできるものを分けること**です。結論を先に書くと、**急ぐ必要があるのは「AI の出力フィールド」と「ニュース本文」の 2 種類だけ**で、市況データ関連はすべて後から追加できます。

---

# 1. 🔑 可逆性マトリクス（最初に読む）

データの種類によって「後から追加できるか」が決定的に違います。**ここを押さえれば、今決めるべき範囲が大幅に狭まります。**

| データ種別 | 後から過去分を取得できるか | 判断の緊急度 |
|---|---|---|
| **AI の出力フィールド**（分類・判定） | ❌ **不可能** — 過去のニュースを再解析できない | 🔴 **入れるなら今** |
| **ニュースの本文・要約** | ❌ **実質不可能** — RSS の遡及は 0.4〜19 日（[08](08-rss-feeds.md)で実測） | 🔴 **入れるなら今** |
| 市況データ（指標の追加） | ✅ **可能** — 履歴 API から取得（下記で実証済み） | 🟢 いつでも |
| N 営業日後の株価実績 | ✅ **可能** — 同上 | 🟢 いつでも |
| 記事 URL・媒体名 | ✅ すでに保存される（`source_urls`） | — |
| 集計・評価ロジック | ✅ 保存済みデータから何度でも再計算できる | 🟢 いつでも |

### 実証: 市況データは後から取れる

```
Yahoo chart API で取得確認済み（2026-11-23 実行）
  S&P500 日足       121 営業日分（2026-05-28 〜 2026-11-20）
  セクターETF       11/11 本 すべて取得成功
  マクロ指標        ドル指数 / WTI / 金 / NASDAQ / ダウ / VIX すべて取得成功
  イールドカーブ    ^IRX(13週) ^FVX(5年) ^TNX(10年) ^TYX(30年) すべて取得成功
```

**つまり「セクター別の実績を見たい」と半年後に思いついても、過去半年分のセクターETF の値は取得できます。** 一方「半年前のニュースをセクター分類したい」は不可能です。

> ### ✅ E-3 解決: `^TNX` は利回りそのまま（×10 ではない）
>
> 懸案だった `^TNX` のスケールが実データで確定しました。
>
> ```
> ^IRX (13週) 4.122    ^FVX (5年)  4.701
> ^TNX (10年) 4.912    ^TYX (30年) 5.303
> ```
>
> 10 年債利回りとして現実的な水準であり、かつ **期間構造（5年 < 10年 < 30年）が整合**しています。`^TNX` は **利回りをそのまま返す**と判断してよい。[00](00-open-items.md) E-3 をクローズします。

# 2. 現状のスキーマで何ができるか

## 2-1. 確定済みの日次 JSON フィールド

```python
{
  "date": "2026-11-20",
  "schema_version": 1,
  "sentiment_score": -3,                 # -5(極度の警戒) 〜 +5(強い楽観)
  "sentiment_summary": "...",
  "news_analysis": [                     # 最大5件
    {
      "headline": "...",
      "summary": "...",                  # 事実と市場予想とのズレ（自由文）
      "horizon": "immediate",            # immediate / short_term / long_term
      "direction": "down",               # up / down / volatility
      "confidence": "high",              # high / medium / low
      "transmission": "...",             # S&P500への波及メカニズム（自由文）
      "source_urls": [...]
    }
  ],
  "watch_list": [{"label":"...", "when":"...", "why":"..."}],
  "market": {
    "spx_close": 6910.39, "spx_change_pct": -3.70,
    "tnx": 4.912, "tnx_change_bp": 12,
    "vix": 35.89
  },
  "report_markdown": "...",
  "x_post_text": "..."
}
```

## 2-2. 日次レポートで出せること

要件のすべてを満たしています。センチメントスコアと総括、重要ニュース最大5件の分析（事実と予想のズレ / 時間軸分類 / 方向性と確度 / 波及メカニズム）、監視リスト、詳細レポート本文、X 投稿文。

## 2-3. 期間レポート（週次・月次・年次）で出せる集計

**[09](09-periodic-reports.md) の設計で、現スキーマから以下が集計できます。**

| # | 集計 | 出力例 |
|---|---|---|
| 1 | センチメント推移 | 「11月のセンチメント平均は -1.4、月後半に急速に悪化」 |
| 2 | センチメントの最高/最低日 | 「最も警戒が強かったのは 11/20（-4）」 |
| 3 | 方向判定の分布 | 「下落要因の判定が 22 日中 16 日で優勢」 |
| 4 | ボラティリティ判定の頻度 | 「ボラ拡大判定が月後半に集中（直近5日で4回）」 |
| 5 | 時間軸判定の分布 | 「中長期影響の判定が前月比で1.8倍に増加」 |
| 6 | 確度分布 | 「確度『高』の判定は全体の 18%」 |
| 7 | S&P500 の期間騰落率 | 「11月は -8.5%」 |
| 8 | 最大上昇日 / 最大下落日 | 「最悪日は 11/20 の -3.70%」 |
| 9 | VIX の平均 / 最大 | 「VIX 平均 24.3、最大 35.89」 |

**日次 22 本を並べるだけでは見えない「流れ」が出る水準には達しています。**

# 3. 現状のスキーマでは「できないこと」

これが拡張を考えるときの出発点です。**答えられない問いを具体的に列挙します。**

| 答えられない問い | 足りないデータ | 後から追加できるか |
|---|---|---|
| **「今月の下落圧力は何が主因だったか」**（金融政策か地政学か業績か） | ニュースのカテゴリ分類 | ❌ |
| **「ハイテクへの言及が集中していたか」** | 影響セクターの分類 | ❌ |
| **「どの銘柄が繰り返し話題になったか」** | 言及銘柄 | ❌ |
| **「予想比で上振れが多かったか下振れが多かったか」** | サプライズ方向の構造化（現在は自由文の中） | ❌ |
| **「既報の蒸し返しか、新規材料か」** | 新規性の判定 | ❌ |
| **「`short_term` / `long_term` 判定は当たっていたか」** | 3/5/20 営業日後の株価実績 | ✅ **可能** |
| **「的中率 58% は『常に強気と言う戦略』に勝っているか」** | ベンチマーク比較 | ✅ **可能**（再計算で足りる） |
| **「方向は当たったが、幅は捉えていたか」** | 騰落幅での評価 | ✅ **可能** |
| **「セクター判定は実際のセクター実績と合っていたか」** | セクターETF の実績 + セクター分類 | ⚠️ **半分だけ可能**（ETF は取れるが分類がない） |
| 「下落はハイテク主導か全面安か」 | NASDAQ / ダウとの比較 | ✅ **可能** |
| 「ドル高・原油高といった外部要因と連動していたか」 | マクロ指標 | ✅ **可能** |

> **最後の行「⚠️ 半分だけ可能」が可逆性の本質を示しています。** セクターETF の実績は後から取れますが、「その日のニュースがどのセクターに効くと判定したか」は後から復元できません。**片方だけ揃っても突き合わせはできません。**

# 4. 追加候補カタログ

## Tier A: AI の出力フィールド 🔴 不可逆

**唯一「今決める」対象。** 追加コストは出力トークンの増加のみ。

| 候補 | 内容 | できるようになること | 出力増 | 月額増 |
|---|---|---|---|---|
| **A1. `news_category`** | 金融政策 / 経済指標 / 企業業績 / 地政学 / 商品 / 規制 / その他 | **原因の分類集計。**「今月の下落圧力は地政学が主因（16件中9件）」 | ~50 | +$0.03 |
| **A2. `affected_sectors`** | GICS 11 セクター（複数選択） | **セクター集計 + ETF 実績との突き合わせ。**「エネルギーは3か月連続で下落要因」 | ~75 | +$0.04 |
| **A3. `mentioned_tickers`** | 言及された個別銘柄 | 銘柄の言及頻度。Seeking Alpha の `category` からも機械取得できる | ~40 | +$0.02 |
| **A4. `surprise_direction`** | 上振れ / 下振れ / 予想通り / 予想なし | **要件の「事実と市場予想とのズレ」を定量化。**「上振れサプライズ7件に対し下振れ3件」 | ~25 | +$0.02 |
| **A5. `novelty`** | 新規材料 / 既報の継続 / 織り込み済み | **「織り込み済みか」の判定を構造化。** 新規材料が市場を動かした率を測れる | ~25 | +$0.02 |
| **A6. `expected_magnitude`** | 大 / 中 / 小 | 確度とは別軸のインパクト評価。「確度は低いが影響が大きい材料」を抽出できる | ~25 | +$0.02 |

**A4 は要件に直接対応しています。** 「ニュース概要（事実と市場予想とのズレ）」は当初要件に明記されていましたが、現在は `summary` の自由文に埋もれており集計できません。構造化すれば月次で「サプライズの方向」を集計できます。

**全部入れた場合: 出力 +240 トークン、月 +$0.15。** 総額 $8.4 → $8.55/月。

## Tier B: 市況データの追加 🟢 可逆・後回し可

**AI のトークンを増やさず、取得も無料。すべて後から過去分を取得できるため急ぎません。**

| 候補 | 取得対象 | できるようになること |
|---|---|---|
| **B1. セクターETF 11本** | XLK / XLF / XLV / XLY / XLC / XLI / XLP / XLE / XLU / XLRE / XLB | **A2 と組めば「セクター別の的中率」が出る。** 単体でも「11月はエネルギーだけプラス」が分かる |
| **B2. 他指数** | ^IXIC（NASDAQ）/ ^DJI（ダウ） | 「下落はハイテク主導か全面安か」。指数間の乖離は相場の性格を示す |
| **B3. イールドカーブ** | ^IRX（13週）/ ^FVX（5年）/ ^TYX（30年） | 金利の期間構造。「長短金利差の縮小」など、10年債単独では見えない動き |
| **B4. マクロ** | ドル指数 / WTI原油 / 金 | 外部要因との連動。「ドル高とハイテク下落の同時進行」 |
| **B5. 出来高** | S&P500 の出来高 | 市場の確信度。「薄商いの下落か、大商いの投げ売りか」 |

**取得コストはゼロ、AI への入力トークンは B1〜B5 全部入れても約 +200（月 +$0.02）。**

> ただし**入力情報を増やしすぎると分析の焦点がぼやける**可能性があります。B1（セクターETF）と B2（他指数）は分析の質に直結しますが、B3〜B5 は「あれば使う」程度。段階的に追加するのが妥当です。

## Tier C: 評価の厚み 🟢 可逆・後から計算可能

**既存の保存データ + 株価履歴から後からいくらでも計算できます。スキーマ変更すら不要なものが多い。**

| 候補 | 内容 | できるようになること |
|---|---|---|
| **C1. N営業日後の実績** | 1 / 3 / 5 / 20 営業日後の S&P500 | **`horizon` 別の的中率。** 現状は `immediate` しか評価できず、`short_term`（2〜5日）と `long_term`（数週間）は**まったく検証されていない** |
| **C2. 騰落幅での評価** | 方向だけでなく変化率で評価 | 「方向は当たったが -0.05% の誤差レベル」を区別できる |
| **C3. ベンチマーク比較** | 「常に上昇」「常に下落」「ランダム」との比較 | **的中率の意味が初めて確定する。** 的中率 58% でも、「常に上昇と言う戦略」が 55% なら優位はわずか 3pp |

**C3 は的中率を解釈するうえで必須です。** S&P500 は長期的に上昇バイアスがあるため、「常に上昇要因と判定する」だけで 50% を超えます。**ベンチマークなしの的中率は無意味に近い。** [09 §3](09-periodic-reports.md) の的中率にはこれを併記すべきです。

## Tier D: 構造的な拡張 ⚠️ 実装が重い

| 候補 | 内容 | 制約 |
|---|---|---|
| **D1. 記事本文のクロール** | RSS 要約ではなく本文を取得 | ❌ 不可逆（過去分は取れない）。実装・トークン・ペイウォールの問題。[00](00-open-items.md) D-1 |
| **D2. 経済指標のコンセンサス** | 市場予想値（雇用統計の予想など） | A4 を機械的に検証できるが、**コンセンサスデータは有料が主**。無料で安定取得できる経路が不明 **[要確認]** |
| **D3. ニュースの Embedding** | ベクトル化して保存 | 意味的な重複排除（現在は文字列類似度）、「過去の類似局面」検索が可能になる。❌ 不可逆だが、本文 or 要約があれば後から生成できるため**実質は可逆** |
| **D4. 個別銘柄の株価** | A3 の銘柄の実績 | 「言及された銘柄は実際に動いたか」。✅ 可逆 |
| **D5. 決算カレンダー** | 決算発表の予定 | `watch_list` の自動補完。無料取得経路は **[要確認]** |

# 5. 原理的にできないこと

拡張しても達成できないものを明示します。**期待値の設定として重要です。**

| できないこと | 理由 |
|---|---|
| **短期の価格予測精度を実用水準まで上げる** | 公開ニュースはすでに価格に反映されている。情報優位がない |
| **因果の特定** | 「このニュースがこの下落を起こした」は観測データから言えない。常に交絡要因がある |
| **少数サンプルでの統計的検証** | 50%→60% の改善検出に 1 群 385 サンプル必要（= 18 か月分）。短期間の A/B テストは原理的に不可能 |
| **過去ニュースの再解析** | RSS の遡及が数日。GDELT は 429、Wayback は RSS スナップショットなし（[08](08-rss-feeds.md) / 検証済み） |

**このシステムの価値は「予測を当てること」ではなく、「毎朝の情報整理を自動化し、判断の材料を一貫した形式で蓄積すること」にあります。** 的中率はその副産物であり、主目的ではありません。

# 6. 推奨する進め方

可逆性マトリクス（§1）を踏まえると、合理的な順序は以下になります。

| 段階 | 内容 | 判断のタイミング |
|---|---|---|
| **① Tier A を決める** | 不可逆なので**今**。推奨は **A1〜A4 の 4 項目**（月 +$0.11） | 🔴 Phase 1 着手前 |
| ② Tier B/C は実装だけ用意 | スキーマに `market` の拡張余地を持たせておく（`dict` 型にして項目追加を許容） | Phase 1 |
| ③ 運用して現スキーマの実力を見る | 2〜4 週間。期間レポートが実際に読めるものになるか | Phase 2 後 |
| ④ Tier B を追加 | 「セクター別に見たい」と実際に思った時点で。**過去分も遡って取得できる** | 運用開始後 |
| ⑤ Tier C を追加 | 的中率が溜まってきた時点（3 か月〜）。**過去分を再計算できる** | 運用開始後 |

## Tier A の推奨（4項目）

| | 推奨 | 理由 |
|---|---|---|
| A1 `news_category` | ✅ **入れる** | 「何が主因だったか」は期間レポートの中核。これがないと「下落要因が16件」までしか言えない |
| A2 `affected_sectors` | ✅ **入れる** | B1（セクターETF）と組んで初めて価値が出る。**ETF は後から取れるが分類は取れない**ため、こちらだけ先に入れる必要がある |
| A3 `mentioned_tickers` | ✅ **入れる** | コストが最小（+$0.02）。Seeking Alpha から機械取得もできる |
| A4 `surprise_direction` | ✅ **入れる** | **当初要件「事実と市場予想とのズレ」の構造化。** 現在は自由文に埋もれて集計できない |
| A5 `novelty` | 🔶 **保留** | 興味深いが、A1・A4 と判定が重複しがち。プロンプトの複雑さが増す |
| A6 `expected_magnitude` | 🔶 **保留** | `confidence` と混同されやすい。先に `confidence` の運用実績を見るべき |

**A1〜A4 の 4 項目で月 +$0.11、総額 $8.5/月。** A5・A6 は保留とし、運用して A1〜A4 の使い勝手を見てから判断するのが妥当です（ただし後から追加はできないため、保留＝永久に入れない選択に近いことは認識しておく必要があります）。
