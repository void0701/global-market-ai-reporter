# 05. 決定事項と未確定事項

最終更新: 2026-11-22

## A. 確定した設計判断

### A-1. 基盤・モデル

| # | 判断 | 理由 |
|---|---|---|
| A-1 | Bedrock は **`bedrock-mantle` エンドポイント**を使う（`bedrock-runtime` の `InvokeModel` は使わない） | Messages API 互換で構造化出力が素直に使える。boto3 での JSON 手組みが不要。[02](02-bedrock-selection.md) |
| A-2 | Python クライアントは **`AnthropicBedrockMantle`**（`anthropic[bedrock]`） | 同上。Lambda では実行ロールが自動で使われ認証コードが不要 |
| A-3 | **モデルは `anthropic.claude-opus-5`** | 因果推論タスクであり出力品質が成果物の価値に直結する。Sonnet 5 との月額差は約 $4 で、この差で品質を落とす合理性が薄い |
| A-4 | **リージョンは `ap-northeast-1`（東京）** | コンソール運用・CloudWatch ログ確認が日本時間の感覚と一致。全リソースを同一リージョンに揃える |
| A-5 | **IaC は Terraform** | CDK の bundling の Docker 依存が、本件の重い依存（pandas 問題）と衝突する。zip の作り方を自分で制御できる方がデバッグが容易 |
| A-6 | **秘密情報は Secrets Manager**（SSM Parameter Store ではない） | リソースポリシー・CMK 連携・CloudTrail 統合による権限分離と監査性。月 $0.40 はその対価 |
| A-7 | **グローバルエンドポイント**を使う（リージョナルの 10% プレミアムを払わない） | 公開ニュースの解析でデータ所在地要件がない |

### A-2. モデル差し替え可能性（A-3 の付随要件）

| # | 判断 | 理由 |
|---|---|---|
| A-8 | モデルIDは **Terraform 変数 → Lambda 環境変数 `BEDROCK_MODEL_ID`** で注入する | 差し替えが tfvars 変更 + apply だけで完了。コード変更・zip 再ビルドが不要 |
| A-9 | **IAM の Resource と使用モデルIDを同じ Terraform 変数（`allowed_model_ids`）から生成する** | 環境変数だけ変えて IAM が旧モデル ARN のままだと `AccessDeniedException` になる典型的な事故を防ぐ |
| A-10 | CLI に **`--model` オプション**を用意し、同じ入力で複数モデルの出力を比較できるようにする | 差し替え前の品質比較を dev で行うため |

手順の詳細は [06 §6](06-cicd-and-environments.md) 参照。

### A-6. Terraform 構成（[06](06-cicd-and-environments.md)）

| # | 判断 | 理由 |
|---|---|---|
| A-32 | **環境別ディレクトリ**構成（`terraform workspace` は使わない） | `workspace select` の実行漏れというサイレントな事故を防ぐ。「prod に適用するには prod ディレクトリに入る」という物理的な区別を作る |
| A-33 | **`aws_secretsmanager_secret_version` を Terraform で管理しない** | **Terraform state には属性値が平文で保存される。** Secrets Manager を選んでも state 経由で漏れれば本末転倒。容器だけ作り、値は手動で 1 回投入する |
| A-34 | X の認証情報を **GitHub Secrets 経由で Terraform に渡さない** | 同上 |
| A-35 | state バケットは**機密情報扱い**（バージョニング + CMK 暗号化 + Block Public Access + `prevent_destroy`） | 同上 |
| A-36 | state ロックは **S3 ネイティブロック（`use_lockfile`）** を第一候補とする | DynamoDB テーブルが不要になる。未対応バージョンなら DynamoDB 併用 |
| A-37 | `infra/bootstrap/` をローカル state の独立構成として**人間が 1 回だけ apply** する | state 置き場と OIDC の鶏と卵問題を解決。変更頻度が極低いため手動で問題ない |
| A-38 | `.terraform.lock.hcl` を**コミットする** | CI とローカルでプロバイダバージョンが揺れるのを防ぐ |

### A-7. CI/CD（[06](06-cicd-and-environments.md)）

| # | 判断 | 理由 |
|---|---|---|
| A-39 | AWS 認証は **GitHub OIDC**。アクセスキーを GitHub Secrets に置かない | 長期有効な認証情報をリポジトリ設定に残さない。GitHub 側に保存する秘密情報がゼロになる |
| A-40 | OIDC 信頼ポリシーで **`aud` と `sub` を完全一致で絞る** | `sub` 条件の省略や広いワイルドカードは、**任意の GitHub リポジトリからロードを引き受けられる**重大な設定ミスにつながる |
| A-41 | IAM ロールを **3 つに分ける**（`gha-plan` 読み取り専用 / `gha-deploy-dev` / `gha-deploy-prod`） | PR の plan に書き込み権限を与えない |
| A-42 | `gha-deploy-prod` の `sub` を **`environment:prod`** に紐付ける | GitHub Environments の必須レビューを通らないとトークンが発行されず、**IAM レベルで承認ゲートが強制される**。ワークフロー書き換えでも迂回できない |
| A-43 | **prod は自動デプロイしない**（手動トリガー + 必須レビュー） | 1 日 1 回のバッチでデプロイ頻度を上げる必要がない。安全側に倒す |
| A-44 | **`pull_request_target` は使わない** | フォークの変更に権限付きで実行されるため、OIDC と組み合わせると危険 |
| A-45 | スモークテストは **`dry_run: true`** で行う | デプロイ検証のたびに Bedrock を呼んで課金されるのを避ける。配線確認が目的 |
| A-46 | Lambda zip は **S3 経由**でデプロイ | 直接アップロードの 50MB 制限を構造的に回避。pandas を含めることになっても詰まらない |
| A-47 | Lambda アーキテクチャは **x86_64**（arm64 にしない） | arm64 は単価が約 20% 安いが Lambda コストは無料枠内で $0。**削減額ゼロの最適化のためにクロスアーキテクチャのビルド複雑性を抱えない** |
| A-48 | Lambda の**予約済み同時実行数を 2** に設定 | 暴走時のコスト上限 |
| A-49 | `main` ブランチを保護（PR 必須 / 必須ステータスチェック / force push 禁止） | — |

### A-12. データ保持方針（[11](11-data-retention.md)）

| # | 判断 | 理由 |
|---|---|---|
| A-82 | **AI のトークンコストを制約とせず、データを最大限保持する** | 後から再解析するため |
| A-83 | **「保存するデータ」と「AI に渡すデータ」を分離する** | 保存はトークン 0。入力を増やすと分析の焦点がぼやけるため選別する |
| A-84 | **RSS 全記事を重複排除前の全件、要約の切り詰めなしで保存する** | **これが可逆性の大半を回収する。** 保存すれば後から別スキーマで再解析できる |
| A-85 | 重複排除の **`cluster_id` / 類似度 / アルゴリズムとパラメータも保存する** | 閾値や手法を変えて同一データで再実験できるようにする |
| A-86 | **プロンプト全文・スキーマのハッシュ・生レスポンス・usage を保存する** | プロンプト改善の効果を同一条件で検証するため |
| A-87 | **`thinking.display: "summarized"` を指定して推論要約を保存する** | **課金は display 設定によらず同一。追加コストゼロで推論過程が残る** |
| A-88 | 市況データは **40 系列を保存し、AI に渡すのは 15 系列のみ** | セクターETF 11 系列は保存のみ（後から判定との突き合わせに使う） |
| A-89 | OHLCV 全項目（始値・高値・安値・終値・出来高）を保存する | 「寄りから売られたか引けにかけて崩れたか」を後から分析できる |
| A-90 | **3 層データモデル**（`raw/` 生データ → `data/` 解析結果 → HTML） | 層ごとに役割と可逆性が違う |
| A-91 | **再解析 CLI（`reanalyze` / `recluster`）を Phase 1 で用意する** | これがないと「後から解析する」が実現しない |
| A-92 | 再解析結果は**別ファイルに書く**。一括実行前に**コスト見積もりを表示して確認を取る** | 元データを壊さない。1 年分の再解析は約 $70 |
| A-93 | `recluster`（重複排除の再実験）は **AI を呼ばない**（無料で何度でも） | パラメータ探索を気軽にできるようにする |
| A-94 | **ライフサイクルルールは設定しない**（無期限保持） | 年 76MB・月 $0.002。削る理由がない |
| A-95 | **[10](10-schema-capabilities.md) Tier A の保留 2 項目（`novelty` / `expected_magnitude`）も採用**。`key_numbers` を追加 | トークンを制約としない方針のため。`key_numbers` が「事実と予想のズレ」を機械検証可能にする |

| A-99 | **円建てリターンを「株価要因 + 為替要因」に分解して表示する** | ドル建てで下落しても円建てで上昇する状況が頻発する。分解がないと判断材料にならない |
| A-100 | **センチメントスコアを 2 本持つ**（`sentiment_score` / `acwi_sentiment_score`） | 米国固有材料・非米国材料・為替要因の 3 ケースで両者は乖離する |
| A-101 | `news_analysis[]` に **`region_focus` / `scope` / `fx_impact`** を追加 | 特に `fx_impact` — 「日銀利上げ」は S&P500 では脇役だが**円建てオルカンには直撃**する |
| A-102 | **別レポートにはせず 1 本の統合レポートにする** | ニュースが共通で重複が多い。X 投稿も倍になる |
| A-103 | **プロンプトに MSCI ACWI の地域構成比（米国約60%）を明記する** | 明記しないと米国固有ニュースをオルカンにも同程度の影響と評価してしまう |
| A-104 | **プロンプトに「円安はオルカン円建てにプラス」を明記する** | 直感に反する論点であり、モデルが混乱しうる |
| A-105 | 期間レポートに**リターンの寄与度分解**を追加 | 「今月の下落は世界株安か円高か」が月次で分かる。最も価値が高い集計 |

### A-14. Phase 1 実装で確定（2026-11-23）

| # | 判断 | 理由 |
|---|---|---|
| A-106 | **Bedrock 呼び出しはストリーミングを既定とする**（`max_tokens=32000`） | 非ストリーミングは SDK が **21,333 超で `ValueError`**。拡張スキーマで出力が 15K 前後になりうる（[00 G-1](00-open-items.md)） |
| A-107 | **市況の基準日はレポート日の前日**（`market_asof_for`） | 07:00 JST = 前日 17:00 ET。当日のセッションはまだ存在しない（[00 G-2](00-open-items.md)） |
| A-108 | **全市況系列を米国株セッション日に揃える** | 為替・商品は 24 時間取引。揃えないと寄与度分解が異なる期間の比較になる（[00 G-3](00-open-items.md)） |
| A-109 | **媒体あたりの選抜上限 `max_per_feed = 4`**。超過分はラウンドロビンで補充 | FT の総合フィードが選抜の過半を占めた実測への対処。rank 順補充では偏りが戻る（[00 G-4](00-open-items.md)） |
| A-110 | 市況取得の既定は **`HttpChartProvider`**（標準ライブラリのみ）。`yfinance` は任意実装 | 全 40 系列の取得を実機確認済み。pandas 非依存なので Phase 2 の軽量化が前倒しで完了 |
| A-111 | Markdown → HTML は**自前の最小実装** | `markdown` パッケージを増やさない。見出し・箇条書き・強調・リンクのみで足りる |
| A-112 | 認証情報エラーは**専用の例外と案内文**にする | 生のスタックトレースではなく、`aws configure sso` と `--dry-run` を案内する |
| A-113 | 「最大上昇日」ではなく**「期間中で最も良かった日」** | 下落週では最良日も負値になり、「上昇」というラベルが誤解を招く |
