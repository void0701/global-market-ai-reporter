# 11. データ保持方針（最大保持）

最終更新: 2026-11-23

**方針: AI のトークンコストを制約とせず、後から再解析できるようデータを最大限保持する。**

---

# 1. 🔑 前回の説明を訂正します

[10](10-schema-capabilities.md) で「AI の出力フィールドは後から追加できない（不可逆）」と説明しました。これは **「ニュース記事を保存しない」という暗黙の前提での話**でした。

**記事を全件保存すれば、後から別のスキーマで再解析できます。** 保存済みの記事を Bedrock に再投入するだけです。

| | 記事を保存しない場合（従来の前提） | **記事を全件保存する場合（本方針）** |
|---|---|---|
| AI 出力フィールドの追加 | ❌ 不可逆 | ✅ **再解析で事後追加可能** |
| 重複排除アルゴリズムの変更 | ❌ 不可逆 | ✅ **再実験可能** |
| プロンプトの改善効果の検証 | ❌ 不可能 | ✅ **同じ入力で比較可能** |
| 捨てた記事の見直し | ❌ 不可能 | ✅ **可能** |
| Embedding の後付け生成 | ❌ 不可能 | ✅ **可能** |

**記事の全件保存が、可逆性の大半を回収します。** これが本方針の最大の効果です。

### 残る制約

| 制約 | 内容 |
|---|---|
| **再解析にはコストがかかる** | 1 日分の再解析が約 $0.27。1 年分（約 260 日）で **約 $70** |
| **モデルが変わる** | 半年後の再解析は当時と違うモデルになる可能性があり、時系列の一貫性が崩れる |
| **記事本文は依然として不可逆** | 保存するのは RSS の要約。本文クロールを後から過去分に適用することはできない |

→ **だからこそ、最初から AI 出力を厚くしておく価値があります。** 再解析コストを払わずに済み、時系列の一貫性も保てます。

# 2. 設計原則: 「保存するデータ」と「AI に渡すデータ」を分離する

これが本方針の中核です。両者を混同すると、トークン削減のためにデータを捨てることになります。

```
RSS 全記事（約200件）─────┬──► 【保存】全件・要約の切り詰めなし    ← トークン 0
                          │
                          └──► 重複排除 ──► 上位15件 ──► 【AIに渡す】

市況データ（約40系列）────┬──► 【保存】全系列の OHLCV              ← トークン 0
                          │
                          └──► 主要15系列のみ ──► 【AIに渡す】
```

**保存はストレージコストだけ（年 $0.02 程度）で、AI のトークンを一切消費しません。** 一方 AI への入力は、情報過多で分析の焦点がぼやけるのを避けるため選別します。

> ⚠️ **「AI に渡す情報を増やせば分析が良くなる」わけではありません。** 40 系列の市況データを全部渡すと、モデルの注意が分散して主要な論点がぼやけます。**保存は最大限・入力は選別**が正しい設計です。

# 3. 3 層データモデル

```
s3://bucket/
├── raw/                        ← Layer 1: 生データ（AIに渡さないものも全件）
│   ├── news/YYYY-MM-DD.json           RSS全記事 + 重複排除の判定結果
│   ├── market/YYYY-MM-DD.json         全系列のOHLCV
│   └── llm/YYYY-MM-DD.json            プロンプト全文・生レスポンス・usage
├── data/                       ← Layer 2: 解析結果（構造化）
│   ├── daily/YYYY-MM-DD.json
│   ├── weekly/YYYY-Www.json
│   ├── monthly/YYYY-MM.json
│   └── yearly/YYYY.json
└── (HTML)                      ← Layer 3: 公開物
```

## Layer 1-a: `raw/news/YYYY-MM-DD.json`

**重複排除で捨てた記事も含め、取得した全記事を保存します。**

```json
{
  "schema_version": 1,
  "collected_at": "2026-11-24T07:00:12+09:00",
  "window": {"from": "2026-11-23T07:00:00+09:00", "to": "2026-11-24T07:00:00+09:00"},
  "feeds": [
    {"name": "CNBC Top News", "url": "...", "http_status": 200,
     "item_count": 30, "latest_item_age_hours": 5.7, "fetch_ms": 412, "error": null}
  ],
  "articles": [
    {
      "id": "sha1:...",
      "feed_name": "CNBC Top News",
      "title": "...",
      "summary_raw": "...",            // ★切り詰め前の全文
      "summary_len": 665,
      "link": "...",
      "guid": "...",
      "published": "2026-11-23T21:30:34-05:00",
      "categories": ["xle", "xlu"],    // Seeking Alpha のティッカー等
      "title_normalized": "...",       // 正規化後（重複排除の再実験用）
      "cluster_id": 3,                 // 重複排除のクラスタ
      "is_representative": true,       // クラスタ代表に選ばれたか
      "similarity_to_representative": 1.0,
      "selected_for_analysis": true    // AIに渡したか
    }
  ],
  "dedupe": {"algorithm": "jaccard+difflib", "threshold": 0.75,
             "input_count": 213, "cluster_count": 31, "selected_count": 15}
}
```

**`cluster_id` / `similarity_*` / `dedupe.algorithm` を保存する理由:** 後から閾値 0.70 や別アルゴリズムで再クラスタリングし、**どちらが良かったかを同じデータで比較できる**ようにするため。アルゴリズムのパラメータも記録します。

## Layer 1-b: `raw/market/YYYY-MM-DD.json`

**AI に渡さない系列も含め、取得した全系列の OHLCV を保存します。**

```json
{
  "schema_version": 1,
  "series": {
    "^GSPC": {"open":..., "high":..., "low":..., "close": 6910.39, "volume":...,
              "prev_close":..., "change_pct": -3.70, "date": "2026-11-20"},
    "ACWI": {...}, "USDJPY=X": {...}, "2559.T": {...}, "XLK": {...}
  },
  "fetch_errors": []
}
```

OHLCV 全項目が取得できることを実機確認済み（`open` / `high` / `low` / `close` / `volume`）。**始値と高安を保存すれば、後から「寄り付きから売られたのか、引けにかけて崩れたのか」を分析できます。**

## Layer 1-c: `raw/llm/YYYY-MM-DD.json`

```json
{
  "schema_version": 1,
  "model": "anthropic.claude-opus-5",
  "region": "ap-northeast-1",
  "request": {
    "system": "...",                   // ★プロンプト全文
    "user": "...",
    "output_schema_hash": "sha1:...",  // スキーマの版を同定
    "max_tokens": 24000
  },
  "response": {
    "stop_reason": "end_turn",
    "thinking_summary": "...",         // ★推論の要約（下記）
    "content_raw": "..."               // 構造化出力のJSON文字列そのまま
  },
  "usage": {"input_tokens": 5210, "output_tokens": 9430,
            "cache_read_input_tokens": 0},
  "latency_ms": 48120,
  "estimated_cost_usd": 0.2616
}
```

### プロンプト全文を保存する理由

**プロンプトを改善したとき、「出力が良くなったのはプロンプトのおかげか、その日のニュースが分かりやすかったのか」を区別できないと改善が検証できません。** プロンプトとスキーマのハッシュを記録しておけば、同一条件での比較ができます。

### 💡 推論の要約が無料で取れる

Bedrock では `thinking.display: "summarized"` を指定すると、モデルの推論の要約が返ります。**課金は `display` 設定によらず同一**（思考トークンはどの設定でも同じだけ billing される）ため、**追加コストなしで推論過程を保存できます**。

デフォルトは `"omitted"`（思考ブロックが空文字で返る）なので、**明示的に `"summarized"` を指定します**。後から「なぜこの判定になったか」を検証できる価値は大きく、コストがゼロなら入れない理由がありません。

# 4. 保存する市況データ（全 40 系列）

**すべて取得可能であることを実機確認済み**（2026-11-23）。AI に渡すのは太字の 15 系列のみ。

| 分類 | 系列 | AIに渡す |
|---|---|---|
| **主要指数** | **`^GSPC`**（S&P500）、**`^IXIC`**（NASDAQ）、**`^DJI`**（ダウ）、`^RUT`（ラッセル2000） | 3/4 |
| **全世界株式** | **`ACWI`**（MSCI ACWI・USD）、`VT`、`URTH`、`VEU` | 1/4 |
| **円建て全世界株** | **`2559.T`**（MAXIS 全世界株式 ETF・JPY）、`1554.T` | 1/2 |
| **為替** | **`USDJPY=X`**、`EURJPY=X`、`EURUSD=X` | 1/3 |
| **ボラティリティ** | **`^VIX`**、`^VXN`（NASDAQ版） | 1/2 |
| **金利** | `^IRX`(13週)、`^FVX`(5年)、**`^TNX`**(10年)、**`^TYX`**(30年) | 2/4 |
| **セクターETF** | `XLK` `XLF` `XLV` `XLY` `XLC` `XLI` `XLP` `XLE` `XLU` `XLRE` `XLB` | 0/11 ※ |
| **地域ETF** | **`EWJ`**(日本)、**`VGK`**(欧州)、**`EEM`**(新興国)、`FXI`(中国)、`INDA`(インド) | 3/5 |
| **コモディティ** | **`CL=F`**(WTI)、**`GC=F`**(金)、`HG=F`(銅) | 2/3 |
| **ドル指数** | **`DX-Y.NYB`** | 1/1 |

※ セクターETF は**保存のみ**。AI には渡さず、後からセクター判定（`affected_sectors`）との突き合わせに使う。11 系列を入力に入れると分析の焦点がぼやけるため。

# 5. ストレージコスト **[試算]**

| Layer | 1 日あたり | 1 年あたり |
|---|---|---|
| `raw/news/` | 約 130 KB（記事 200 件 × 650 B） | 約 34 MB |
| `raw/market/` | 約 12 KB（40 系列 × OHLCV） | 約 3 MB |
| `raw/llm/` | 約 70 KB（プロンプト + レスポンス + 推論要約） | 約 18 MB |
| `data/` | 約 20 KB | 約 5 MB |
| HTML | 約 60 KB | 約 16 MB |
| **合計** | **約 290 KB** | **約 76 MB** |

**S3 Standard（東京）で年 76 MB → 月額 約 $0.002。** 10 年運用しても 760 MB で月 $0.02。

**実質ゼロです。ライフサイクルルールも不要**（[00](00-open-items.md) D でレポート保持期間を「無期限」と判断済み。生データも同様）。

> **PUT リクエスト課金:** 1 日 5〜6 オブジェクト × 22 日 = 月約 130 回。$0.005/1,000 リクエストなので **月 $0.001**。無視できます。

# 6. AI 出力フィールドの拡張（全採用）

トークンを制約としない方針のため、[10](10-schema-capabilities.md) Tier A の**保留 2 項目を含めて全採用**し、さらにオルカン対応分を追加します。

## 6-1. `news_analysis[]` の各要素

| フィールド | 状態 | 内容 |
|---|---|---|
| `headline` / `summary` / `transmission` / `source_urls` | 既存 | |
| `horizon` / `direction` / `confidence` | 既存 | |
| **`news_category`** | 追加 | 金融政策 / 経済指標 / 企業業績 / 地政学 / 商品 / 規制 / その他 |
| **`affected_sectors`** | 追加 | GICS 11 セクター（複数選択） |
| **`mentioned_tickers`** | 追加 | 言及された個別銘柄 |
| **`surprise_direction`** | 追加 | 上振れ / 下振れ / 予想通り / 予想なし |
| **`novelty`** | 追加 | 新規材料 / 既報の継続 / 織り込み済み |
| **`expected_magnitude`** | 追加 | 大 / 中 / 小 |
| **`key_numbers`** | 追加 | 実績値・市場予想・前回値を構造化（`{label, actual, consensus, previous, unit}`） |
| **`region_focus`** | 追加 | 米国 / 欧州 / 日本 / 新興国 / 中国 / グローバル（[12](12-global-index.md)） |
| **`scope`** | 追加 | 米国固有 / 全世界共通（同上） |
| **`fx_impact`** | 追加 | 円安要因 / 円高要因 / 中立（同上） |

**`key_numbers` が「事実と市場予想とのズレ」を初めて機械検証可能にします。** 現在は `summary` の自由文に「予想を上回る」と書かれるだけで、数値が構造化されていません。

## 6-2. トップレベル

| フィールド | 状態 | 内容 |
|---|---|---|
| `sentiment_score` / `sentiment_summary` | 既存 | S&P500 向け |
| **`acwi_sentiment_score`** / **`acwi_sentiment_summary`** | 追加 | 円建て全世界株式（オルカン）向け（[12](12-global-index.md)） |
| **`fx_outlook`** | 追加 | 為替の見通しコメント |
| `watch_list` / `report_markdown` / `x_post_text` | 既存 | |

## 6-3. ⚠️ フィールドを増やすことの唯一の実質的リスク

**コストではなく品質です。**

必須フィールドが増えると、モデルの注意が分散し、**中核である `transmission`（波及メカニズム）や `summary` の記述が薄くなる**可能性があります。また、判定に迷うフィールドを機械的に埋める（全部「その他」にする等）挙動も起こりえます。

これは**運用して確認するしかありません**。[09](09-periodic-reports.md) の期間レポートでフィールドの充填率と分布を集計し、以下を監視します。

| 監視指標 | 異常のサイン |
|---|---|
| `news_category` の分布 | 「その他」が 50% を超える |
| `affected_sectors` の平均選択数 | 常に 1 個、または常に 5 個以上 |
| `surprise_direction` の分布 | 「予想なし」が 80% を超える |
| `transmission` の平均文字数 | 拡張前より明確に短くなる |

**充填率が低いフィールドは削る**という逆方向の判断も、記事を保存しているため（再解析で検証できるので）安全に行えます。

# 7. 再解析の仕組み（Phase 1 で用意する）

保存した生データから再解析するための CLI を最初から用意します。**これがあって初めて「後から解析する」が実現します。**

```bash
# 保存済み記事を別スキーマ・別プロンプトで再解析（HTMLは上書きしない）
python -m market_report.cli reanalyze --date 2026-11-24 --out-suffix v2

# 期間を指定して一括再解析（コスト見積もりを表示して確認を取る）
python -m market_report.cli reanalyze --from 2026-11-01 --to 2026-11-30 --dry-run-cost

# 重複排除だけ別パラメータで再実行（AI呼び出しなし・無料）
python -m market_report.cli recluster --date 2026-11-24 --threshold 0.70
```

### 設計上の要件

| 要件 | 理由 |
|---|---|
| **再解析結果は別ファイルに書く**（`--out-suffix`） | 元の解析結果を壊さない。比較のために両方必要 |
| **一括実行前にコスト見積もりを表示して確認を取る** | 1 年分の再解析は約 $70。意図しない大量実行を防ぐ |
| **`recluster` は AI を呼ばない** | 重複排除の実験は無料で何度でもできるようにする |
| **当時のモデル ID を記録・再指定できる** | 時系列の一貫性を保った再解析ができる（そのモデルが提供されている限り） |
